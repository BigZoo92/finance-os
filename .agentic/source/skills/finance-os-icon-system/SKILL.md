# Finance-OS icon system

Three tiers, in strict order. Semantic correctness always beats visual preference.

```text
1. Pixel Icon   default for essentially everything
2. Phosphor     only when Pixel has no clear metaphor
3. Pxlkit       rare expressive moments only
```

## Decision algorithm

```text
What concept must this icon communicate?

Does the vendored Pixel set contain a clear equivalent?
  yes -> use it.

Is there a clear Pixel icon upstream but not yet vendored?
  yes -> add it to scripts/vendor-pixel-icons.mjs, regenerate, use it.

No clear Pixel equivalent, or Pixel is ambiguous/illegible at the real size?
  -> pick the best Phosphor icon and say why in a comment or the PR note.

Is this surface deliberately expressive, and would a pixel-art asset
materially improve it (celebration, signature empty state, premium accent)?
  -> only then consider Pxlkit.

Otherwise -> do not use Pxlkit.
```

Never pick Pixel just to honour the order when its metaphor is weaker than the fallback.

## Tier 1 — Pixel Icon (default)

Catalogue: <https://www.shadcn.io/icons/pixel> (the HackerNoon Pixel Icon Library, 24px grid).
Do not confuse it with Pixelarticons or other pixel sets.

Icons are **vendored**, not depended on:

- Components live in `packages/ui/src/icons/pixel/<name>.tsx`, one file per icon.
- They are generated by `scripts/vendor-pixel-icons.mjs` from the upstream `.svg`. Never hand-edit a generated file; add the name to `ICONS` and rerun the script.
- No runtime dependency and no download from shadcn.io at build or run time.

```tsx
import { SearchPixelIcon } from '@finance-os/ui/icons/pixel'

<SearchPixelIcon size={16} />
```

The barrel is a curated, hand-sized set of pure re-exports, so it tree-shakes. Keep it that way: every vendored icon must have a real consumer. To bypass the barrel, import `@finance-os/ui/icons/pixel/<name>`.

Artwork is CC BY 4.0 — attribution is required and lives in `docs/third-party-notices.md`. Verify the upstream licence before vendoring anything new.

## Tier 2 — Phosphor fallback

Package: `@phosphor-icons/react` (MIT), a dependency of `apps/web`.

**Import granularly, never from the package root or as a namespace:**

```tsx
import { BellSimpleIcon } from '@phosphor-icons/react/dist/csr/BellSimple'
```

```tsx
// Never do either of these.
import * as Icons from '@phosphor-icons/react'
import { BellSimpleIcon } from '@phosphor-icons/react'
```

Root imports make Vite traverse thousands of modules in dev; namespace imports defeat tree-shaking entirely.

### csr vs ssr in this repo

Use `dist/csr/*` **everywhere in `apps/web`**, including components that render on the server.

`@phosphor-icons/react/ssr` exists for React Server Components, where `IconContext` is unavailable. Finance-OS runs TanStack Start's classic SSR + hydration, not RSC, so `useContext` resolves normally on the server and `IconContext` defaults (`currentColor`, `regular`) apply. Do not transpose the Next.js App Router rule here. If a future surface genuinely becomes RSC, verify the package's `exports` map before using any `ssr` path — do not guess subpaths.

Styling: let the icon inherit `currentColor`, keep `regular` weight by default, `bold` only where small-size legibility needs it, `fill` for a genuinely informative active state. Avoid `duotone` — it sits poorly next to pixel artwork. Do not vary weights arbitrarily between equivalent screens.

## Tier 3 — Pxlkit (rare)

Source: <https://github.com/joangeldelarosa/pxlkit>. **Currently not installed and not used** — no surface has justified it.

It is not Phosphor's fallback. Valid only for a specific expressive moment: celebration/success, a signature empty state, a premium accent, a well-chosen micro-interaction. Never for navigation, tables, forms, CRUD actions, ordinary buttons, dense lists, filters, menus, or as decoration.

If one is ever justified: install only `@pxlkit/core` plus the exact pack needed, prefer a static icon over `AnimatedPxlKitIcon`, respect `prefers-reduced-motion`, and check the accessible semantics of the rendered `<img>`/SVG. Pxlkit code is MIT but its **icon assets are separately licensed** (attribution required, with paid no-attribution terms) — verify `LICENSE-ASSETS` upstream and document attribution before shipping any asset.

Pxlkit may stay an expressive special case; do not force it behind the same API as the plain SVG icons.

## Performance rules

- No `import * as Icons`.
- No dynamic/runtime icon registry, and no `<Icon name="anything" />` lookup component.
- No barrel that re-exports hundreds of icons.
- Keep imports statically analysable so route-level code splitting survives.
- Do not install icon packs that have no consumer.

## Accessibility

- Decorative icon next to text: keep it hidden. Vendored pixel icons already default to `aria-hidden="true"`.
- Icon-only control: give the control an accessible name.

```tsx
<button type="button" aria-label="Actualiser">
  <RefreshPixelIcon size={16} />
</button>
```

- A tooltip is not a substitute for an accessible name.
- If an icon carries information no adjacent text provides, put `role="img"` + `aria-label` on its wrapper and leave the icon decorative.
- Never communicate state through icon, colour, or animation alone — always pair with text.

## Visual rules

- Colour comes from Finance-OS tokens via `currentColor`; no hardcoded hex in components.
- Pixel identity is controlled micro-expression. Financial data stays dominant.
- Test legibility at the real rendered size. A 24px-grid pixel icon is not automatically readable at 11px — check dense contexts.
- Keep optical alignment with adjacent text (`inline-flex`/`items-center`, not a bare inline SVG on the baseline).
- Do not change button sizes or touch targets when swapping an icon; keep 44px mobile targets.
- Typographic marks are not icons: brand glyphs, keycaps (`⌘K`), trend arrows next to amounts, and flow connectors stay as text.

## Migration rule

Never replace icons by matching names alone. For each site: identify the intent, choose by the algorithm above, then preserve semantic meaning, state, accessibility, interaction, layout, and visual hierarchy. Icon work is not licence to redesign a page.

Read `DESIGN.md` and the `finance-os-command-pixel` skill for the surrounding visual system.
